Page E · Model Swap

修改模型：把 A 的样子换到 B 身上，先体检、再预览、最后注入

设计目标：把「角色 A 的模型换成角色 B」做成一条可以检查的流程——先确认设备与游戏状态，再确认两头在同一个骨架集， 预览确认纹理与骨骼，最后才注入。三条底线：预览不撒谎（缺纹理就说缺纹理、解析失败写原因）；规则不越界（跨骨架集直接拒绝，不赌一次）； 效果可还原（不写存档、不改游戏文件，停止注入即完全还原）。

02 · Nine States

九种状态：每个失败都要有下一步

九态共用一套骨架「体检 → 映射 → 预览 → 主 CTA」，只换行尾文案与提示条，不做整页重排；所有失败态都必须给一个可点的出口。

03 · Rules

角色与骨架集：先拒绝，再动手

换模型是在游戏内存里改「角色 id → 模型」的映射，配对错了不会报错、只会看起来不对。所以所有校验都放在点击之前。

配对校验

校验项 / 规则 / 失败文案

6 条
校验项规则失败文案
空选 A 与 B 都必须从受控下拉里选中，不接受空值 先选角色 A，再选同一骨架集的角色 B
id 长度 角色 id 上限 64 个字符 角色 id 超过 64 个字符，请重新选择
非法字符 只允许字母、数字、下划线与短横线 角色 id 含非法字符，只接受字母、数字、下划线与短横线
A = B A 与 B 必须是不同 id，同一个 id 替换没有意义 A 与 B 是同一个角色，换一个目标
跨骨架集 只允许同一骨架集内部互换：chara_1 / chara_2 / chara_3 / chara_4 / chara_other 互不通用 两个角色不在同一骨架集（chara_1 与 chara_2），会缺骨架、比例错乱
输入方式 只允许从下拉选择，不提供手动输入 id 的入口 只能从列表中选择角色，不支持手动输入

校验顺序从「能不能选」到「能不能配」：空选 → 长度 → 字符 → 同 id → 同骨架集，任何一条不过就不渲染预览，也不点亮 CTA。

04 · Safety

安全边界：能还原才敢改

换模型碰的是运行时内存，不是文件。边界写清楚，用户才敢把一个角色的外观换到另一个角色身上。

五条边界

写进界面文案，而不是只写在文档里

可还原
  • 需要 root：三行体检里 root 不绿，换模型不可用，其余功能照常，界面不弹红。
  • 不写存档、不改游戏文件：只改内存里的模型引用；停止注入即完全还原，不需要备份。
  • 改规则不热重载：已加载的模型不会自己刷新，要重进场景或重启游戏才看得到新外观。
  • 跨骨架集不做：缺骨架、比例错乱的「看起来像」不提供，宁可拒绝也不赌一次。
  • 注入器没起来，规则写了也不生效：所以未启动时主 CTA 先变成「部署并启动注入」。
一句话口径：这条流程只做三件事——确认环境、确认配对、把映射写进内存；不碰文件、不留痕迹、随时可停。
